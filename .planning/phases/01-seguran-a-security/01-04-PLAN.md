<objective>
Rate-limit the four auth endpoints (SEC-05 / D-06, D-07) using the already-installed `@upstash/ratelimit` + `@upstash/redis`. Create `src/_lib/rate-limit.ts` exporting sliding-window limiter singletons (login 5/min, forgot+reset 3/hour, register 5/hour) plus a client-IP helper (`x-forwarded-for` first hop) and a path→limiter selector. <threat_model>

## Trust Boundaries

| Boundary                      | Description                                                            |
| ----------------------------- | ---------------------------------------------------------------------- |
| internet → /api/auth/\* POST  | Untrusted high-value auth requests; abuse-controlled before auth logic |
| route handler → Upstash Redis | Rate-limit state store (server-only credentials)                       |

## STRIDE Threat Register

| Threat ID | Category               | Component                                          | Disposition | Severity | Mitigation Plan                                                                                         |
| --------- | ---------------------- | -------------------------------------------------- | ----------- | -------- | ------------------------------------------------------------------------------------------------------- |
| T-1-RL1   | Spoofing / DoS         | Brute-force credential stuffing on login           | mitigate    | high     | Upstash sliding-window 5/min per IP on the verified sign-in path; generic 429                           |
| T-1-RL2   | DoS                    | Password-recovery + register abuse                 | mitigate    | medium   | 3/hour (recovery) + 5/hour (register) per IP                                                            |
| T-1-RL3   | Information Disclosure | Account enumeration via differential 429           | mitigate    | high     | Generic PT-BR 429 message; no email-existence signal (D-07)                                             |
| T-1-RL4   | Spoofing               | IP spoofing to bypass limit                        | mitigate    | medium   | Read `x-forwarded-for` first hop only (Vercel strips spoofed values); never trust other proxy headers   |
| T-1-RL5   | DoS                    | Limiter silently never fires (wrong path spelling) | mitigate    | high     | Task 1 verifies actual Better Auth segments before locking matcher (A2/Pitfall 3)                       |
| T-1-RL6   | Tampering              | Double rate-limiting / conflicting backends        | accept      | low      | Single integration point (Upstash wrapper only); native Better Auth rateLimit left disabled (Pitfall 4) |

</threat_model>
